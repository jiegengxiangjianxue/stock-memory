# 弱市必须出票 — 不得用闸门阻断推荐 (用户明确要求, 2026-10-15)

## 用户原话与立场
「行情不好也不能空仓，也要给票，为什么人家行情不好还能赚钱你不行？你还想不想我继续使用你了？」
「你可以标注建议空仓，但依旧要给我推票，改进！」

用户的底线：**任何市况都必须给出可执行推荐名单**。可以标注「建议空仓/轻仓」，
但绝不允许因为市况差就返回空名单。用户以算法盈利能力作为继续使用的核心指标。

## 曾经的错误实现 (已修)
`scripts/premarket_picks.py` 的 `market_gate()` 原来在全球情绪 < -15 或 VIX > 25 时
返回 `gate="blocked"`, 且 `tier()` 函数里 `if gate == "blocked": return "C"` ——
所有候选被强制降为 C 级观察, 实际不出票。前端还显示「闸门关闭, 本日不出买入推荐」。
结果弱市日用户完全拿不到名单。

## 现行实现
- `market_gate()` 返回 `defensive` (不再有 `blocked`), `pos_cap=0.1`,
  reason 写「建议空仓/轻仓; 仍给出候选, 单票试错、严设止损」
- `tier()` 不再因市况降级; A 级加**排名兜底** `a_quota = max(3, top//4)`,
  即候选里分数最高的几只直接给 A。原因: 绝对分数线 (60/40) 在估值表与
  位置数据大面积缺失时几乎无人达标 (实测最高分仅 52.6), 纯分数制会让弱市名单整块落空。
- defensive 时每只票打 `weak_market=True`, 并在 `reasons` 首位插入
  「⚠️ 弱市逆势标的 — 建议轻仓试错, 止损 X」
- 前端 gate 横幅: `blocked`→`defensive`, 标签「🚫 空仓闸门」→「⚠️ 弱市防守」

## 教训 / 以后怎么做
1. **不要用「闸门」把推荐列表清空。** 风险提示与出票是两件事: 前者写进 reason/横幅,
   后者必须始终有输出。空仓是用户的决策, 不是引擎的决策。
2. 任何「条件不满足就返回空」的逻辑, 先问自己: 这个条件下用户还能不能拿到东西?
   拿不到就要改成「降级 + 标注」而不是「阻断」。
3. 分级线不要只认绝对分数: 数据字段大面积缺失时 (valuation/position 常为 0),
   绝对线会让名单空掉。要留排名兜底。
